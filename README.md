# 乐小读

乐小读是拥有公司知识的独立 AI 对话应用。它可以像普通 AI 一样自然聊天和回答一般问题；需要公司资料时，会从方舟知识库中自动选择相关文件，不需要顾问手动上传，也不依赖本地原文档副本。

## 当前工作流程

1. 管理员从独立备份中选择 PDF、DOCX、PPTX、XLSX 公司原文档，直接本地上传到方舟非结构化知识库，并等待解析成功。
2. 启动乐小读并新建或选择一个会话。
3. 顾问直接描述家长顾虑或追问问题。
4. 应用读取知识库中已解析完成的四类文档，豆包根据当前会话和云端文件名自动选择最多三份相关原文档。
5. 应用把选中文档的 `doc_id` 合并为一次方舟检索，并将检索证据交给豆包回答。

多文档必须合并检索；逐文档连续调用曾触发方舟标准版 `1000029` QPS 限流。仅选择 DOCX、PPTX、XLSX 时，最终 Responses 生成使用 120 秒单次请求超时；包含 PDF 的请求保持当前客户端默认行为。

每个会话拥有独立上下文。AI 可以自行判断、追问和组织表达，但公司事实必须以原文档为依据。

## 通用对话与顾问沟通

乐小读始终与正在使用应用的公司顾问交流，但不会把每个问题都当成家长沟通任务。普通聊天和直接提问会自然回答；只有顾问明确需要家长沟通建议或话术时，才进入顾问话术模式。历史按原始用户/助手轮次保留，每轮只执行最新用户消息，旧截图仍属于原来的消息；“不发链接、只发文字、简短回答”等明确要求会持续生效，直到顾问改变要求。

家长是顾问需要沟通和服务的对象。即使称为“顾问老师”，公司顾问也只负责家长沟通，不是孩子的授课老师、班主任或课堂管理人员。聊天案例只用于概括表达结构、语气和异议处理方法，不能作为公司政策、课程信息或承诺的事实来源。

- 信息不足时，乐小读向顾问说明缺少的关键情况，并只追问一至两个聚焦问题，不假装直接询问家长。
- 信息充分时，回答先给出“给顾问的建议”，再给出“可直接发给家长”的一段独立纯文本话术。
- 学习困难、亲子沟通和一般学习习惯等不涉及公司事实的问题可以不选文档、不调用知识检索，直接给出双段建议。
- 家长话术始终站在顾问身份表达。课堂观察、教学调整、作业讲解等动作会区分授课老师或实际责任人；反馈、转达或协调其他岗位必须有公司知识或实际流程依据，否则只提示顾问核实。
- 知识库来源文件名、适用条件和待核实事项只放在顾问说明中，不混入可复制的家长话术。
- 课程名额、订单、付款和 App 显示等实时状态仍需查询业务系统；知识库未支持的公司事实不会由聊天案例或常识补造。

## 当前支持范围

- 独立聊天窗口，以及会话的新建、选择、搜索、重命名和删除。
- 按会话保存上下文，明确区分“顾问”和“乐小读”。
- 本地加密保存会话与消息。
- 顾问可在输入区选择一张 PNG、JPG、JPEG 或 WebP 聊天截图；长截图以 `high` 细节模式交给模型理解。
- 从方舟知识库自动发现已解析的 `PDF`、`DOCX`、`PPTX`、`XLSX` 原文档。
- 自动选择最多三份相关文件。
- 通过方舟知识库读取并使用 PDF、DOCX、PPTX、XLSX 的正文、表格和幻灯片内容。
- 无公司资料依据时明确提示待核实，不编造公司事实。
- 对课程名额、订单、付款和 App 显示等实时信息，要求查询业务系统。
- 对退款、投诉、法律、安全、健康、隐私和儿童保护事项，提示人工核实。

截图不支持 OCR、粘贴、单条消息多图、本地切片、TOS、方舟 Files API 或图片知识库上传。

## Windows 安装版

公司内部安装包已经预配置运行所需的豆包和方舟知识库参数。顾问按默认步骤安装后，从桌面或开始菜单双击“乐小读”即可使用，不需要安装 Python、打开命令行或填写配置。

每台电脑的聊天、DPAPI 密钥、截图和日志保存在当前 Windows 用户的 `%LOCALAPPDATA%\Lexiaodu`。覆盖安装、卸载和重装不会主动删除这个目录。

## 源码启动

当前电脑在项目根目录执行：

```powershell
.\.venv\python.exe -m lexiaodu
```

也可以指定配置文件：

```powershell
.\.venv\python.exe -m lexiaodu --config config\app.toml
```

## 方舟配置

复制环境变量模板：

```powershell
Copy-Item .env.example .env
```

在本机 `.env` 中填写：

```dotenv
LEXIAODU_GENERATOR=doubao
ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
ARK_MODEL=填写方舟模型名称
ARK_API_KEY=填写方舟模型推理APIKey
VOLC_ACCESSKEY=填写火山引擎AccessKey
VOLC_SECRETKEY=填写火山引擎SecretKey
VOLC_REGION=cn-beijing
ARK_KB_COLLECTION=填写非结构化知识库名称
ARK_KB_PROJECT=default
ARK_KB_HOST=api-knowledgebase.mlp.cn-beijing.volces.com
```

`.env` 已被 Git 忽略，不要提交、打印或发送真实密钥。

`ARK_MODEL` 必须支持图片理解；截图会编码为 Base64 并通过 HTTPS 发送到方舟。

如只想检查聊天界面，可临时设置：

```dotenv
LEXIAODU_GENERATOR=simulated
```

模拟模式不会读取公司资料，也不会生成正式业务回答。

文档链路需要在华北区域开通方舟知识库，并完成一次人工导入：

1. 在方舟控制台进入“数据管理 → 知识库”，创建“非结构化数据”知识库；默认切片规则即可，记录知识库名称。
2. 从公司独立备份中选择 PDF、DOCX、PPTX、XLSX 原文件，在“导入文档”中选择“本地上传”。
3. 等待每份文档处理成功，并在“切片详情”或“知识检索”中抽查解析和召回结果。
4. 创建具有该知识库读取和检索权限的访问密钥，把 AK/SK 只写入本机 `.env`。

知识库目前仅支持华北区域，并会产生知识库用量费用。应用只列出并检索知识库，不上传、更新或删除云端文档。文件更新时，请在控制台从独立备份重新上传，确保知识库中只保留一个有效版本。

方舟控制台也支持 TOS 导入，但当前项目决定以后直接本地上传；TOS 桶由管理员独立处理，不属于乐小读代码、配置或运行时依赖。应用不读取 `TOS_BUCKET`、`TOS_ENDPOINT`，也不创建 TOS 客户端。

方舟正式说明：[文档知识问答核心流程](https://www.volcengine.com/docs/82379/1261883?lang=zh)、[知识库插件功能说明](https://www.volcengine.com/docs/82379/1528458?lang=zh)。

## 维护公司原文档

公司原文档统一由管理员在方舟知识库中维护。文件名应清晰描述内容，因为豆包会参考云端文件名选择文档。应用只把 `process_status=0` 且扩展名为 PDF、DOCX、PPTX、XLSX 的文档作为候选，并使用方舟返回的 `doc_id` 在一次请求中限定所有选中文档的检索范围。

排查文档回答失败时，应分别核对云端目录是否存在同名文档、`process_status` 是否为 0、限定 `doc_id` 的检索结果是否为空，以及方舟调用是否返回错误码；不能把这四类情况统一当作文档缺失。

项目内 `company_documents/` 已在确认独立备份、云端清单和无本地副本运行结果后删除。应用不会重新创建、扫描或要求该目录；原文件恢复与后续上传均以独立备份为准。

当前文件能力：

- `PDF`、`DOCX`、`PPTX`、`XLSX`：人工导入方舟知识库并长期保留，应用从云端目录自动选择并按 `doc_id` 检索，官方解析结果会参与豆包回答。

本地不会对这些文件执行 OCR、正文提取或文本切段。

## 数据与隐私

- 用户数据目录：`%LOCALAPPDATA%\Lexiaodu`
- 聊天数据库：`%LOCALAPPDATA%\Lexiaodu\chat.sqlite3`
- 本地加密密钥：`%LOCALAPPDATA%\Lexiaodu\chat.key`
- 聊天截图：`%LOCALAPPDATA%\Lexiaodu\chat-images\`；原图按会话加密保存，删除会话时一并删除。
- 脱敏日志：`%LOCALAPPDATA%\Lexiaodu\logs\lexiaodu.log`
- 公司原文档：保存在管理员确认的独立备份中，需要更新时直接本地上传方舟知识库。
- 项目内 `company_documents/` 已删除且不参与运行；应用不会重新创建该目录。
- TOS 桶由管理员独立处理，不属于应用的数据路径。
- 应用对知识库只读，不上传、更新或删除 PDF 或 Office 文档。
- 应用不会直接向家长发送消息，最终内容由顾问确认和使用。

长截图使用 `high` 细节模式，不在本地切片。测试截图只可使用合成或脱敏内容，禁止使用真实家长数据。

不要删除 `%LOCALAPPDATA%\Lexiaodu\chat.key`，否则既有加密聊天记录将无法读取。

## 开发环境

项目要求 Python 3.11。安装核心依赖和测试依赖：

```powershell
.\.venv\python.exe -m pip install -e ".[dev]"
```

运行测试：

```powershell
.\.venv\python.exe -m pytest -q
```

## 构建 Windows 安装包

构建机需要 Python 3.11、项目本地 `.venv` 和 NSIS 3。真实凭证只保存在 Git 忽略的 `.env`；构建脚本只筛选运行必需的 10 个配置项，不携带完整 `.env` 或 TOS 配置。

```powershell
.\.venv\python.exe -m pip install -e ".[dev,build]"
.\.venv\python.exe tools\build_windows_release.py
```

如 `makensis.exe` 不在常见安装目录，可用 `MAKENSIS_PATH` 指定。最终安装包和单页 `使用说明.pdf` 输出到 Git 忽略的 `release\`；安装包只能通过公司内部私密渠道分发。
