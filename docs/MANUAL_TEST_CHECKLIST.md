## 完整流程

统一使用 `docs/DEMO_SCRIPT.md` 的虚构消息。

| ID | 操作 | 通过标准 | 结果/证据 |
|---|---|---|---|
| F-01 | 不设置 `LEXIAODU_UI_MODE` 并启动应用 | 打开独立聊天窗口，不出现悬浮工具条；会话栏、消息区和输入区无截断 |  |
| F-02 | 新建会话，重命名，按标题和消息搜索，再清空搜索 | 每步都更新会话栏；选中项始终对应实际会话 ID，同名会话不会串选 |  |
| F-03 | 建立两个标题和内容相近的会话，只在其中一个输入唯一虚构哨兵，再来回切换和追问 | 两个会话的消息、OCR 校正文案和回复卡互不混入；另一会话的回复不引用哨兵 |  |
| F-04 | 在默认窗口发送多轮虚构消息 | 每轮先显示用户消息再显示助手消息；助手明确说明是离线演示且不会查询或编造公司事实 |  |
| F-05 | 完成消息、截图 OCR 校正和一条现有回复卡记录后，完全退出并重启 | 同一会话的消息、校正文案和回复卡恢复；没有自动重发未完成请求 |  |
| F-06 | 框选单屏区域，等待 OCR，修改错字和发言人后确认 | UI 不冻结；原图只形成随机名加密 `.bin`；确认文字只进入截图开始时所属会话 |  |
| F-07 | 人为让一次助手请求失败，再点击原消息上的“重试” | 失败状态可操作；重试沿用原请求且最终只出现一条助手回复 |  |
| F-08 | 复制一个加密附件作测试备份后损坏原 `.bin`，再尝试读取 | 应用明确提示附件无法解码，不显示乱码、不崩溃；测试后恢复或删除虚构附件 |  |
| F-09 | 删除含附件的虚构会话，退出并重启 | 会话、消息、OCR 校正文案、回复卡均不再出现，加密附件文件也已删除 |  |
| F-10 | 在独立聊天窗口和 OCR 校正窗口按 `Ctrl + +` / `Ctrl + -`，再打开新窗口并重启 | 已打开及随后打开窗口同步逐级变化且无截断；重启后恢复“系统字号 + 1pt” |  |
| F-11 | 预置一条高风险回复卡，验证确认门控并编辑复制 | 未确认时复制禁用；确认后复制的是编辑后文本，反馈仍只保存结构化元数据 |  |
| F-12 | 设置 `$env:LEXIAODU_UI_MODE='legacy'` 后启动 | 只出现原置顶悬浮工具条，截图、OCR、建议和关闭流程仍可用；测试后清除该环境变量 |  |

## 隐私、安全与异常路径

| ID | 操作 | 通过标准 | 结果/证据 |
|---|---|---|---|
| P-01 | 默认聊天截图前后检查项目目录 | 没有新增 PNG/JPG/BMP 或以聊天内容命名的文件；只允许随机文件名的加密 `.bin` 增加 |  |
| P-02 | 用唯一虚构哨兵完成一次流程后，以原始字节检查 `data/chat.sqlite3*`、`data/chat-attachments/`、`artifacts/` 和 `*.log` | 找不到哨兵、OCR 校正文案或回复卡正文的明文字节；加密数据库和附件可增加 |  |

| P-04 | 断开或禁用 OCR 后截图 | 显示可操作错误，能用手动粘贴继续 |  |
| P-05 | 临时移走知识索引后生成 | 明确提示知识索引错误，不编造制度依据 |  |
| P-06 | 使用退款、投诉、安全、隐私、欺凌各一条虚构问题 | 均为高风险且必须转人工 |  |

| P-08 | 在同一 Windows 账号下由另一测试人员启动应用 | 能看到同一份本地会话，确认共享账号不是隐私隔离边界 |  |

## 本轮状态说明

当前开发机已完成离屏 UI 自动化、加密重启恢复、线程隔离、删除清理和代码级隐私验证。上表的实体电脑项目（尤其是 DPAPI 跨账号边界、损坏附件、真实屏幕缩放和旧版回滚）必须由执行人在最终演示电脑上逐项填写；未填写项一律视为“未验证”，不能据此宣称手工验收通过。
