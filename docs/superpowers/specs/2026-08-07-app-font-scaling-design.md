# 乐小读全局字号调节设计

## 目标

- 乐小读图形界面启动后，所有窗口的字号默认比系统默认字号大 1pt。
- 用户可在应用任一窗口内使用 `Ctrl + +` 和 `Ctrl + -`，每次将全局字号增大或减小 1pt。
- 快捷键调整仅在当前进程内有效；重启后恢复为“系统默认字号 + 1pt”。
- 保留标题、正文和辅助文字之间已有的字号层级。

## 范围

本次覆盖应用创建的全部 Qt 窗口，包括悬浮工具条、截图选择界面、OCR 文字校正窗口、AI 问答窗口和顾问建议窗口。命令行输出、操作系统界面以及其他程序不受影响。

不增加设置页面、字号按钮、配置文件字段或跨进程持久化。除字号变化外，不调整窗口尺寸、配色、间距或业务交互。

## 设计

新增一个应用级字号控制器，由程序创建 `QApplication` 后立即安装：

1. 记录 Qt 提供的系统默认应用字体大小。
2. 启动时把当前字号设为系统默认值加 1pt。
3. 在应用级事件过滤器中识别 `Ctrl + +`、数字键盘 `Ctrl + +` 和 `Ctrl + -`。
4. 每次触发后更新 `QApplication` 的字体，使已有窗口和后续创建的窗口使用同一字号级别。
5. 将应用基础字号限制在 8pt 至 24pt；达到边界后继续按键不再变化，并消费该快捷键，避免输入控件产生意外字符。

控制器只管理当前字号和快捷键，不依赖聊天、OCR 或工作流业务对象。

AI 页面和悬浮工具条目前包含少量显式像素字号。它们将改为以现有视觉字号换算出的点字号为基准，加上同一个运行时字号增量，并在应用字体变化时刷新自身样式：标题仍大于正文，分节标题和风险标签仍小于或等于正文。其他未显式指定字号的控件继续继承应用字体。

## 事件与状态流

启动时：

`系统默认字体 -> 字号控制器加 1pt -> QApplication 字体 -> 所有窗口继承或刷新相对样式`

运行时：

`任一窗口收到 Ctrl 加/减键 -> 应用事件过滤器 -> 更新当前字号 -> QApplication 通知窗口 -> 显式样式刷新`

所有状态仅保存在内存中，不读取或写入用户配置。

## 边界与兼容性

- 只有同时按下 Ctrl 的加号或减号键才调整字号；普通输入不受影响。
- 输入框获得焦点时快捷键仍由应用统一处理。
- 同时兼容主键盘和数字键盘产生的加减按键。
- 不增加 `Ctrl + 0` 或其他未要求的快捷键。
- 使用 Qt 的点字号，避免把固定像素字号误当成系统 DPI 缩放。
- 系统字体未提供有效点字号时，以 9pt 为基准，再应用默认加一级。
- 快捷键仅在乐小读处于活动状态时生效；按住快捷键产生的自动重复事件会继续逐级调节。

## 验证

自动化测试先于实现添加，并覆盖：

- 控制器启动后比传入的系统基准字号大 1pt。
- `Ctrl + +` 与 `Ctrl + -` 每次改变 1pt。
- 输入控件持有焦点时快捷键仍生效。
- 最小、最大边界不会越界。
- 新建窗口继承当前字号。
- AI 页面与悬浮工具条的相对字号随全局字号变化。

完成后运行字号控制器的聚焦测试、聊天/OCR/工具条回归测试，以及完整测试套件。手动检查至少包含默认显示、AI 建议长内容滚动、OCR 表格布局和连续缩放后的按钮文字截断情况。
