# 乐小读精简核心版设计

日期：2026-08-10

## 目标

将项目收敛为一个以豆包为主体的独立顾问聊天应用：保留加密会话、独立上下文、自动选择公司原文档和 PDF 原文件上传；彻底移除已经废弃的本地知识库、OCR、截图附件、旧回复卡、反馈和本地风险流程。

## 保留范围

- 独立聊天主窗口，以及会话的新建、选择、搜索、重命名、删除和失败重试。
- 当前 Windows 用户范围内加密保存的会话和消息。
- `company_documents/` 原文件目录，以及豆包基于会话和相对路径自动选择最多三份文档。
- PDF 原始字节上传方舟并参与回答；回答后删除方舟临时文件。
- DOCX、PPTX、XLSX 的发现和选择入口，但在方舟文档知识库接通前明确提示不可读取。
- 人工顾问最终决定如何使用 AI 回答，应用不直接向家长发送消息。

## 删除范围

- 本地知识库检索、知识导入、OCR、语义筛选、policy 升级和所有相关命令行入口。
- 截图附件存储、OCR 校正文案、旧回复卡、结构化反馈、旧建议生成器和旧本地风险模块。
- 未接入运行流程的文档目录/规则路由器、失效的“生成正式回复”按钮和右侧资料抽屉。
- 上述功能对应的测试、评测脚本、配置项、依赖和生成产物。
- PaddleOCR、PaddlePaddle、OpenCV、pypdf 等仅由旧流程需要的软件；重新建立只包含当前运行和测试依赖的虚拟环境。

公司原文档、现有加密会话和消息不在删除范围内。旧截图附件、OCR 文本、反馈库和生成测试产物属于已确认删除范围。

## 上下文与回答

- 每条历史消息发送给豆包时必须标明“顾问”或“乐小读”，不能继续使用无角色的文本拼接。
- 在字符预算内按时间顺序保留尽可能完整的当前会话，不跨会话读取；超出预算时从最早消息开始裁剪。
- 系统提示保留三条硬边界：公司事实只能来自本轮提供的公司原文档；实时业务状态必须让顾问查询业务系统；退款、投诉、法律、安全、隐私和儿童保护等高风险问题不得给出确定承诺，应提示人工核实。
- 窗口和应用名称统一为“乐小读”。

## 数据迁移

- 保留 `conversations`、`messages` 和加密密钥。
- 启动时移除旧附件、OCR、回复卡、反馈相关表或记录，并删除 `data/chat-attachments/` 与 `data/feedback.sqlite3`。
- 数据库迁移必须幂等，重复启动不能影响现有会话和消息。

## 验收

- 默认启动路径不再导入或实例化知识库、OCR、附件、回复卡、反馈和旧风险模块。
- 界面只保留有效聊天功能，没有截图、附件、资料抽屉和正式回复按钮。
- 当前会话上下文具有角色标签且不串线；重启后会话和消息仍可恢复。
- PDF 自动选择和原文件上传测试通过，Office 未接通时给出明确提示。
- 项目全量测试通过，依赖检查通过，虚拟环境明显缩小。
