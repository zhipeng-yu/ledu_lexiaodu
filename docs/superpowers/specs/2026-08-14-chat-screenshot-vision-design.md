# 乐小读聊天截图视觉输入设计

- 日期：2026-08-14
- 状态：设计已确认，等待书面规格复审
- 范围：PySide6 顾问聊天窗口、加密会话存储和豆包回答链路

## 目标

顾问可以从文件选择器向当前会话添加一张个人聊天或群聊截图。乐小读把截图随相关会话上下文发送给火山方舟上的豆包视觉模型；信息不足时向顾问追问一个关键问题，信息充分时继续输出“给顾问的建议”和“可直接发给家长”。

截图在本机加密保存，应用重启后仍可查看和用于失败重试；删除会话时同时删除截图。长截图直接使用方舟 `high` 图片细节模式，首版不自行切片。

## 非目标

- 不支持剪贴板粘贴、截图捕获或单条消息多图。
- 不使用本地 OCR、本地视觉模型、TOS、方舟 Files API 或知识库图片上传。
- 不保存视觉转写、参与者列表或图片摘要等派生副本。
- 不新增视觉专用模型配置；继续使用 `ARK_MODEL`。
- 不在没有真实验收证据前增加长图切片。
- 不直接向家长发送消息。

## 用户流程

1. 顾问选择当前会话，点击输入区的“选择图片”。
2. 文件选择器只允许选择一张 PNG、JPG、JPEG 或 WebP 图片。
3. 输入区显示缩略图；顾问可以移除或重新选择，也可以补充文字。
4. 有图片时允许正文为空；空正文保存为“聊天截图”，有正文则原样显示，两种情况都附带缩略图。
5. 后台处理期间沿用现有请求状态。失败后“重试”使用同一张加密截图，不要求重新选择文件。
6. 豆包无法确定群聊中的顾问、家长或其他成员身份时，乐小读只向顾问追问一个最关键的身份问题，不生成家长话术。
7. 信息充分时沿用现有双段回答格式和公司事实边界。

图片选择只形成内存草稿。顾问发送后才保存消息和加密原图；移除草稿或关闭窗口不留下附件文件。

## 数据与隐私

新增截图附件记录，包含随机附件 ID、会话 ID、用户消息 ID、随机加密文件路径、加密数据密钥、MIME 类型、宽高和创建时间。原文件名不持久化。

原始图片字节使用每附件随机数据密钥加密；该数据密钥再使用现有 `DataCipher` 加密。附件文件以随机 `.bin` 名称保存到项目数据目录。保存采用临时文件加原子替换；数据库写入失败时删除刚创建的文件。

读取附件必须同时提供会话 ID 和消息 ID，不能只凭附件 ID 跨会话读取。删除会话前读取其附件路径，确认解析后的路径直属截图附件目录，再删除加密文件和会话记录。文件删除失败时保留会话并提示删除失败，避免界面声称已删除而磁盘仍残留附件。

截图会通过 HTTPS 发送到火山方舟推理接口，但乐小读不把它写入 TOS、Files API 或知识库。方舟平台自身的数据处理与日志保留仍由账号配置和服务条款决定。

## 模型调用与上下文

`ContextBuilder` 在现有字符预算内选择消息。每次模型请求最多携带一张截图：当前请求绑定截图时使用该图；纯文字追问使用所选上下文中最近一张截图；重试始终使用原请求绑定的截图。新截图进入上下文后，不再把更早截图发送给模型，但历史界面仍可显示它们。

模型请求把文本上下文和图片 Base64 数据放在同一个多模态用户输入中，图片细节固定为 `high`。正文为空的截图消息在模型上下文中使用中性文字“请分析这张聊天截图”。

现有文档选择调用和最终回答调用都接收选定截图，因此豆包可以依据截图判断是否需要公司资料，并基于同一原图生成追问或建议。纯文字追问会继续发送最近截图，直到新截图替代它或该截图消息被上下文预算裁掉；旧请求重试仍使用原请求截图。不建立额外解析缓存。

知识文档链路保持不变：仍只读取方舟知识库中已解析的 PDF、DOCX、PPTX 和 XLSX，最多选择三份并统一检索。图片不能成为公司政策、课程、价格或承诺的事实来源；这些事实仍必须来自知识库证据。

系统提示增加以下最小约束：

- 图片可能是个人聊天或群聊，参与者身份优先依据昵称、气泡方向和上下文判断。
- 身份或关键事实不确定时明确标记不确定，并只追问顾问一个关键问题。
- 不把截图中的聊天案例当作公司政策或确定承诺。
- 信息充分时继续遵守顾问身份、教学岗位边界和现有双段回答格式。

如果 `ARK_MODEL` 不支持视觉输入，显示可操作错误，要求把现有模型接入点换成支持图片理解的豆包模型；不自动切换模型。

## 长截图策略

首版接受正常可解码且在方舟请求限制内的竖向长截图，不按宽高比拒绝。发送原图并使用 `high` 细节模式，不改变原图、不生成切片。

实施验收至少使用三张人工构造或已脱敏图片：个人聊天长截图、三人以上群聊长截图、身份刻意模糊的群聊截图。只有前两类在 `high` 模式下出现稳定漏读或小字不可辨认，才另行设计内存切片；切片不属于本次范围。

## 错误处理

- 选择阶段验证扩展名、实际图片解码和空文件；失败时不创建消息或附件。
- 加密保存失败时不发送请求，并清理本次已创建的临时文件。
- 附件丢失、损坏或无法解密时，请求进入现有失败状态并允许重试；不把空图片当作成功输入。
- 方舟拒绝图片、模型不支持视觉或网络调用失败时，保留消息和附件，沿用现有失败/重试入口。
- 删除附件失败时不删除会话记录，并向顾问显示明确错误。
- 应用重启时仍把处理中请求标为 interrupted，不自动重新上传截图。

## 验证

自动化验证覆盖：

- 原图和数据密钥不以明文落盘；篡改密文后读取失败。
- 截图严格按会话和消息隔离，不能跨会话加载。
- 发送纯图片消息、图片加文字消息、移除草稿和失败重试。
- 每次模型请求最多发送一张正确归属的截图；文字追问复用最近截图，新截图替换更早截图，旧请求重试仍使用原图。
- 重启后恢复截图消息和缩略图；删除会话后附件文件消失。
- Chat Completions 文档路由和 Responses 知识回答都携带同一图片，且细节模式为 `high`。
- 个人聊、群聊、身份不确定、无需公司资料和需要公司资料的提示词契约。
- 既有纯文字聊天、文档选择、知识检索、角色边界和全量测试无回归。

真实方舟验收只使用人工构造或已脱敏截图，不使用真实家长隐私数据。验收记录图片是否完整可读、身份判断是否合理、追问是否仅一个、建议是否符合现有输出契约。

## 成功标准

- 顾问能选择并发送一张聊天截图，关闭并重启后仍能查看。
- 个人聊和群聊均能得到追问或回复建议；身份不明确时不猜测。
- 长截图在 `high` 模式的验收样例中可用，失败时明确报告而不是静默漏读。
- 图片始终加密落盘、严格会话隔离，并随会话删除。
- 不增加本地 OCR、切片、派生解析存储或新的运行时依赖。
- 全量自动化测试通过。
